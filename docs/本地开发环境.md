## ⚠️ 不入库但不可丢失的本地资产

这几项因体积过大或属于产物而被 `.gitignore` 排除，**换机或重新克隆后必须重新准备**，否则构建会失败：

| 路径 | 体积 | 缺失后果 | 如何恢复 |
|------|------|---------|---------|
| `engine-src/` | 1.9 MB | 编译脚本报 engine source not found | `powershell scripts\fetch-engine.ps1` |
| `pikafish.nnue` | 11.8 MB | 引擎无法加载评估网络 | 同上 |
| `build/` | 8.9 MB | 无 `.so`，需重新编译 | `native\android\build_so.ps1` 或 CI |
| `app/nativeplugins/XiangqiEngine/` | 28.3 MB | HBuilderX 找不到本地插件 | 从 CI Release 下载插件包解压 |

> **提示**：无需本地编译也能拿到插件包 —— 打 tag 触发 Release，
> 下载 `XiangqiEngine-android-release.zip` 解压到 `app/nativeplugins/` 即可。
> 详见 [发布流程](%E5%8F%91%E5%B8%83%E6%B5%81%E7%A8%8B.md)。

## 路径相关注意事项

### 构建脚本不再硬编码绝对路径

`build_so.ps1` 曾把仓库根写死为 `D:\projects\xiangqi-app`，迁移后立即失效。
现已改为从脚本自身位置推导：

```powershell
$ROOT = (Resolve-Path (Join-Path $PSScriptRoot '..\..')).Path
```

iOS 侧的 `build_ios.sh` / `make_framework.sh` 同样使用相对推导：

```bash
ROOT="$(cd "$(dirname "$0")/../.." && pwd)"
```

**因此移动仓库位置不会再破坏构建脚本。** 唯一仍需手改的是 `build_so.ps1`
顶部的 NDK 路径（`$NDK`），换机时按实际安装位置调整。

### ESM 模块声明

`app/package.json` 与根 `package.json` 均声明了 `"type": "module"`，
因为 `app/utils/*.js` 使用 ES module 语法。

Node 按**被导入文件最近的 package.json** 判定模块类型，
所以只在根目录声明是不够的，`app/` 下也必须声明，否则会出现
`MODULE_TYPELESS_PACKAGE_JSON` 警告并带来额外解析开销。
