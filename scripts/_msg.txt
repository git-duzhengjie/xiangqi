feat(endgame): 新增残局挑战，支持取胜/守和两类目标

按老板确认的方案实现：目标判定 A+C（达成即过关、区分胜和）、
残局固定最高难度引擎、首页与难度列表并列展示。

===== 关于 FEN 可靠性的说明 =====

象棋残局对棋子位置极其敏感，差一个兵的位置，胜负结论就可能完全反转，
从「巧胜」变成「必和」甚至「必败」，残局也就失去了挑战意义。

原计划收录七星聚会、蚯蚓降龙、千里独行等古谱十大名局，但这些局面的
精确摆位我无法确证，凭印象构造出来的盘面很可能与真正的名局无关、
胜负结论也未必成立。因此本次只收录 4 个能够确证且经引擎校验的
实用残局，并在数据文件中写明这条原则：
宁可少收录，也不上错局。日后补充古谱名局需以可靠棋谱为依据。

===== 新增文件 =====

app/utils/endgames.js
  残局数据（id / 局名 / 出处 / 目标 / FEN / 简介 / 提示）
  ENDGAME_GOAL 常量、findEndgame、goalText
  含 3 个取胜类（马兵巧胜、炮兵入局、单车擒马）
  与 1 个守和类（单仕守和）

scripts/check-endgames.cjs
  用项目自身规则引擎逐条校验，53 项断言：
  FEN 可解析且回写一致、红方先行、将帅各一枚、棋子在合法区域、
  将帅不照面、开局未被将死或困死、红方着法数 >= 3、
  守和局面黑方确有攻击手段

  校验实际抓出两个问题，均已修正：
  1. 单车擒马原 FEN 将帅同列且中间无子，构成将帅照面的非法局面，
     红方被直接判死、着法数为 0。已将帅移到中路 (9,4)。
  2. 双卒守和原 FEN 红方仅 1 个合法着法，只能走独木桥，
     谈不上防守技巧。已加一仕改为单仕守和，红方有 3 着可选，
     并把「着法数 >= 3」写成硬性门槛防止以后再收录这类局面。

  另外记录一个自己踩的坑：脚本最初凭印象注入了 constants 中并不存在的
  isRed / sideOf，导致 genAllLegalMoves 抛 ReferenceError，
  而校验代码用 try 把异常吞掉，表现为「红方着法数 0」，
  差点让我误判为残局 FEN 写错而去改数据。现已改用真实导出的
  pieceSide / pieceType 等，并去掉吞异常的 try —— 校验脚本必须让
  意外异常直接崩掉，否则它自己就成了错误源。

scripts/test-endgame-goal.cjs
  过关判定测试，18 项断言。核心是验证同一个对局结果在两类目标下
  必须得出相反结论：和棋在取胜类残局是失败、在守和类残局是成功。
  若沿用普通对局逻辑（只认 RED_WIN）这条必然失败。

scripts/check-vue.cjs
  .vue 专用校验：抽出 script 段做语法解析、检查 template 标签配平、
  核对模板引用的方法是否都在 script 中定义。
  原因是 check-syntax.cjs 按纯 JS 解析 .vue 会在 <template> 处
  必然报 Unexpected token，那是脚本适用范围问题；但直接跳过 .vue
  会让首页这类改动完全失去语法保护。

===== 修改文件 =====

app/pages/game/game.js
  新增 startFen 保存本局起始局面，endgame 保存当前残局对象。

  重点修正两处硬编码：engine.think 与 engine.hint 原本都写死
  INITIAL_FEN，残局下引擎会按标准开局盘面推演，走出的着法与实际
  棋盘完全脱节。已改为 this.startFen。

  onLoad 支持 endgame 参数，残局固定取 DIFFICULTY_LEVELS 最后一档
  （少子局面下弱引擎容易随手放水，那样过关没有意义）。
  resetGame 对残局用 parseFen(startFen) 还原，不再回到标准开局。
  新增 endgamePassed 计算属性承载胜/和判定。
  resultText / resultSub / difficultyName 针对残局给出专门文案，
  失败时说明「本局需要取胜，和棋不算过关」，避免用户不知差在哪里。

app/pages/index/index.vue
  新增残局挑战板块，复用 level-card 基础样式，
  用左侧色条与目标标签作区分，守和类用冷色以便一眼分辨两类目标。
  目标判定与文案统一从 ENDGAME_GOAL / goalText 取，
  不在模板里直写 'draw' 字面量，避免日后改常量时漏改、
  或首页与对局页出现两套判断逻辑。
